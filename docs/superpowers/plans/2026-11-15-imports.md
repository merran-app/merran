# Imports in the background, with a history: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Slice 3 of the speed work: every import (one link, a video, the extension, the share sheet, an assistant's suggestion, several links, a starter collection, Mealie, Paprika, a Merran export) runs as a job and leaves a record; one link waits about 10 seconds and then hands over; uploaded files are checked in a job; and a new **Imports** page lists every import with what came in, what was already there and what didn't come in, with Delete, Undo, Restore and Try again, and a notice when one finishes.

**Architecture:** A household-scoped `imports` table and an `import_items` table hold each import's record for 90 days; an import's id is its job's id, so old links to a link import still work. Each import job writes its items as it goes. A single link is a job the request waits on (`JobRunner.waitFor`) for 10 seconds; a video hands over at once. A new `/api/imports` API serves the page; the job event gains who started it, so that person's app shows a notice when it ends.

**Tech Stack:** Hono with @hono/zod-openapi, MikroORM 7 (SQLite and Postgres, migrations for both), the job runner from slice 2, React 19 with TanStack Router and Query, shadcn/ui on Base UI (its `AlertDialog` and `Dialog` become drawers on phones), sonner toasts, the WXT extension.

**Spec:** [docs/performance.md](../../performance.md): slice 3's row in The plan, [The Imports page](../../performance.md#the-imports-page), decisions 1 and 2, and the findings under "Work still inside a request" and "Following background work".

## Global Constraints

- **Single link:** "Every one-link import is a job. The request waits about 10 s and opens the recipe if it's done; otherwise it says the recipe is importing, and the import goes on in the background, with a notice when it's in and its place on the Imports page. … Video links hand over straight away. … The same for the extension, the share sheet … and an assistant's import proposal" (decision 1).
- **Where:** Recipes → ⋯ → **Imports**, with Manage tags, Review, Possible duplicates and Recently deleted. The page a link import opens today (`/recipes/import/$importId`) becomes an import's page there.
- **Listed:** several links, a starter collection, a Mealie backup or export, a Paprika file, Mealie through its API, a Merran export, and a single link or video that went to the background (one that finished while you waited isn't listed). Each says what it was, who started it, when, and how it's going or went: "Importing 12 of 52", or "48 came in, 3 already here, 1 didn't".
- **An import's page:** **Came in** (each recipe, photo, link, checkbox; **Delete** moves the ticked ones to Recently deleted); **Already in your recipes** (each linked); **Didn't come in** (each with why, and **Try again**, which starts a new import of just those; a Mealie connection asks for its token again).
- **Undo** moves everything the import brought in to Recently deleted (30 days). It asks first, saying how many, every recipe ticked, the ones changed, planned or cooked since they came in marked; untick any to keep them. An undone import says so, with **Restore** while its recipes are still in Recently deleted. A running import is stopped first. For a Merran export, Undo covers its recipes only.
- **Notice:** "48 recipes imported", with **View**, from the household `job` event.
- **Kept 90 days**, with **Delete** for the record, which never deletes recipes.
- **Who:** everyone who can add recipes sees every import. Delete and Undo need the right to delete recipes (today `recipes:write`; every member has it). **Try again** on a file or Mealie import is for whoever could start one: household admins, and the server admin for Mealie through its API.
- **Mobile uses drawers:** the app's `AlertDialog` and `Dialog` already become drawers on phones; use them.
- Words people read go in `apps/web/src/locales/en.json`; a string whose meaning changes gets a new key. Styles use logical classes (`ms-*`, `ps-*`, `text-start`), and chevrons along the line get `rtl:-scale-x-100`.
- Routes mirror the API (`GET /api/imports/{importId}` is `apps/server/src/http/routes/imports/[importId]/get.ts`). After API changes: `pnpm --filter @merran/server openapi`, then both `api` scripts (in PowerShell with `pnpm_config_cache_dir` in `.local/`); the two `schema.d.ts` must match.
- Entities change → `pnpm --filter @merran/server db:migration <name>` writes SQLite and Postgres; if Docker won't start, generate Postgres offline from the snapshot (`apps/server/.local/gen-pg-migration.ts`). Postgres foreign keys need `.index()`.
- Guides quote the app's labels exactly and describe main as released.

## Decisions made in this plan (November 15, 2026)

Each goes into performance.md's "What slice 3 built" with the date.

1. **`import_items` rather than `recipes.import_id`.** The page needs a row for every link or recipe that was already there or didn't come in, with its name and why, so items need a table anyway, and each item's `recipe` says what came in. Adding a foreign key column to `recipes` would make SQLite rebuild that table, which cascades into its child rows. `import_items.recipe` is set to null when a recipe is deleted for good, and the import's record cascades its items.
2. **An import's id is its job's id.** Imports and jobs are one to one (Try again starts a new import), so `/recipes/import/{jobId}` links in old share answers and webhook payloads open the import's page, and the job needs no foreign key (jobs are cleared after 30 days, imports after 90).
3. **One link always makes a record, listed only when it hands over.** The record is made with the job, `listed: false`; the request sets `listed: true` if 10 seconds pass first, so a job finishing just as the request gives up can't miss its record. Unlisted records are cleared after a day.
4. **Two kinds for one link:** `recipes.importLink` (long lane, concurrency 3, two per household) for pages, and `recipes.importVideo` (long lane, concurrency 2, one per household), which replaces the in-memory video queue. A batch of links still reads its videos itself, so at most four video downloads run at once rather than two.
5. **The notice goes to whoever started the import,** on every device they have open: the `job` event says who started it (`startedBy`). Others in the household see it on the Imports page.
6. **Try again on a file needs the file.** An upload is kept after an import that had failures, until the daily clean-up's 7 days, rather than deleted on success; past that, Try again says to upload it again.
7. **No `import.finished` webhook for a single link;** it already sends `recipe.created`. The event's `url` points at the import's page for every kind.
8. **The several-links routes that only followed an import go** (`GET /recipes/import/links`, `GET /recipes/import/links/{importId}`, `POST /recipes/import/links/{importId}/stop`): `/api/imports` replaces them, as the spec says. The pull request is marked breaking (`feat!:`).
9. **Imports from before this release aren't listed,** except one still running when Merran restarts, whose job makes its record (`ensureImport`).
10. **Changed, planned or cooked since it came in:** changed is a version saved after it came in, other than its import's; planned is any plan entry with it; cooked is `lastMadeAt` set or a cook note.

## Review Focus

1. **A job finishes in the instant the request hands over.** The record must end listed and finished, not listed and "running" forever, or unlisted and lost. Pinned in Task 6.
2. **Undo after people changed things.** A recipe deleted since, or already in Recently deleted, or planned next week: Undo must skip ones gone for good, never touch other imports' recipes, and Restore must bring back only what Undo moved. Pinned in Task 4.
3. **Try again on a Mealie import whose token is forgotten, or a file past its 7 days.** It must say what to do (enter the token, upload again), not fail with a stack trace. Pinned in Task 5.
4. **A huge app import** (thousands of recipes): the page must not load every item at once or rewrite a growing JSON blob on every recipe. Pinned in Tasks 1 and 3 (items in their own table, the page's lists paged).
5. **Callers that need the recipe at once** (Tonight's idea plans it; the extension opens it) when a link hands over instead: they must say it's still importing and offer the Imports page, not break. Pinned in Task 7.
