# See more everywhere Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Slice 6 of the speed work. Every list that stops short gets **Show more**: each followed site's recipes, starter collections past 24, the recipe pickers past 50, and pages for the assistant's `search_recipes`. Small tiles get a thumbnail instead of the 800×600 card photo.

**Architecture:** Lists page with `offset` and `limit` and say how many there are in all (`total` or `count`), as the library does. The web app loads further pages with `useInfiniteQuery`, adding one page per **Show more**. A third photo size, `thumb`, is made with the other two. Older photos get theirs the first time it's asked for.

**Tech Stack:** Hono with @hono/zod-openapi, MikroORM 7.2 (SQLite and Postgres; `em.countBy`), sharp, the AI SDK, React 19 with TanStack Query 5, vitest (server), node:test (web).

**Branch:** `perf/see-more`, from main after slice 5 (#113).

**Spec:** [docs/performance.md](../../performance.md): slice 6's row in The plan, with its findings in [Library search](../../performance.md#library-search) (the pickers stop at 50, and their tiles download the card photo), [Discover and the shelf](../../performance.md#discover-and-the-shelf) (the Sites tab, the spotlight, starter collections), [The web app](../../performance.md#the-web-app) (small tiles download the card photo, and no image has `decoding="async"`), and [Later: the search revamp](../../performance.md#later-the-search-revamp) (`search_recipes` says it matches tags).

## Decided while planning (November 25, 2026)

For the user to confirm with the plan:

2. **The button says Show more,** as the library's does (`recipes.showMore`), not "See more" as the plan's row puts it.
3. **Pages:** 24 for a site's recipes and for a collection, and 50 for the pickers. **Show more** adds one page at a time. A site shows up to the 120 recipes Merran keeps for it.
4. **A thumbnail size for tiles of 48 px or less:** 160×160 WebP. That covers the pickers, plan tiles, Fill the week and the Imports page. Cards and recipe pages keep the card and full sizes. Older photos get a thumbnail the first time one is asked for. Photos from the shelf and from Discover stay as they are: they're 640×480 already and shown on cards.
5. **The spotlight and Today's idea get up to 24 recipes that suit the household, chosen on the server.** Today they get the newest 24, and the browser drops the ones that don't suit, so the spotlight can show very few.
6. **The Sites tab reads each followed site's first page in one query.** The counts, the library lookup and the household's tastes are read once for every site, not once per site.
7. **`search_recipes` takes an `offset`** and says where the next page starts. Its description stops saying it matches tags; it matches name, description and ingredients. How search matches stays for the search revamp.
8. **Nothing breaks:** only new fields and parameters. A collection's `count` now counts every recipe that suits the household, not just the first 24. The pull request's title is `feat:`.

## Global Constraints

- **Page sizes:**
  - A site's recipes: 24 (`NEWEST`). A site keeps up to 120 recipes.
  - A collection: 24 (`PAGE`). A collection with fewer than 4 that suit the household stays hidden (`FEWEST`).
  - The pickers: 50 (`PICK_PAGE`).
  - Each list's `limit` goes up to 96.
  - `search_recipes`: up to 20, and 10 when `limit` is null.
- **Collection import:** up to 100 links at once (`MAX_LINKS` in `services/recipes/import/import-links.ts`).
- **The spotlight's recipes (`GET /sites/recipes`):** up to 24 that suit the household, newest first, read from the followed sites 48 at a time.
- **The thumbnail:** `thumb: { width: 160, height: 160, fit: "cover", quality: 70 }`, kept as `photos/{householdId}/{photoId}/thumb.webp`. Its link is `/api/recipes/{id}/photo?size=thumb&v={photoId}`.
- **API changes:** run `pnpm --filter @merran/server openapi`, then `pnpm --filter @merran/web api` and `pnpm --filter @merran/extension api`. The two `schema.d.ts` files must be identical. The `api` scripts fail in Git Bash here: run them in PowerShell with `$env:pnpm_config_cache_dir = "D:\Development\Mise\.local\pnpm-cache"`.
- **Routes mirror the API.** `GET /api/sites/{site}/recipes` is `apps/server/src/http/routes/sites/[site]/recipes/get.ts`, and the folder's `index.ts` registers it.
- **Words people read** go in `apps/web/src/locales/en.json`. A string whose meaning changes gets a new key.
- **Code style:**
  - Comments are plain English and say why.
  - Code is written for people to read: no packed one-liners.
  - Logical classes only (`ms-*`, `text-start`).
  - Drawers, not dialogs, on mobile.
- **Prettier** from the root only (`pnpm format`), never on `docs/`.
- **Focused tests:**
  - Server: `pnpm --filter @merran/server exec vitest run --project sqlite <path>`.
  - Web: `pnpm --filter @merran/web test`. Its `test` script in `apps/web/package.json` names each test file, so a new one is added there.

## Review Focus

1. **A photo kept before thumbnails.** Asked for as `thumb`, it's made from the full size once, kept, and served from then on. A photo whose files are gone answers 404, not 500. Pinned in Task 1.
2. **A list that changes between pages.** A site posts a recipe, or one is imported in another tab, between two presses of **Show more**. Offset pages can then repeat a card. A card shows once, and a page that comes back empty ends **Show more** even if `total` says there's more. Pinned in Task 2 (`uniqueById`, `nextOffset`), and used in Tasks 4 and 5.
3. **Import these 24 with recipes that changed meanwhile.** Ids that are no longer in the collection, are now in the library, or are more than 100 are left out. If none are left, it answers 409 as now. Pinned in Task 5.
4. **A page past the end.** A site's or a collection's `offset` beyond its recipes gives an empty page with the right `total`. Pinned in Tasks 4 and 5.
5. **A spotlight whose newest recipes all have something the household avoids.** It still finds older ones that suit, and gives none when none suit. Pinned in Task 4.
