# Webhooks (PR 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A household admin adds a webhook in Settings → Household → Webhooks, and Home Assistant or n8n gets a signed Standard Webhooks delivery whenever a recipe is added, changed, deleted or restored, with retries for about 27 hours, a deliveries log, Send a test, pausing, and the server admin's rule on home-network addresses.

**Architecture:** Services call `record()` inside the transaction that makes the change. It saves a `webhook_events` row and, for each active webhook that wants the event, a `webhook_deliveries` row and a `webhooks.deliver` job. The job signs the envelope and POSTs it through `public-fetch.ts`, retrying on a per-kind schedule the runner gains. Who did it comes from an `AsyncLocalStorage` that a middleware fills after sign-in. The module's `apply()` tells `record()` whether webhooks are on and what the public URL is.

**Tech Stack:** Hono + @hono/zod-openapi (OpenAPI 3.1 `webhooks` through `registry.registerWebhook`), MikroORM 7 (SQLite and Postgres), vitest (server, shared), node:test (web), React + TanStack Query, shadcn/ui on Base UI, Astro Starlight, `standardwebhooks@1.1.1` (dev dependency of `@merran/server`, tests only).

**Spec:** [docs/webhooks.md](../../webhooks.md). Read it first: this plan builds its first pull request ("Build order", item 1), and argues from it.

**Where:** the branch `feat/webhooks`, from `origin/main`, in the worktree `.claude/worktrees/webhooks`. Its first commit ("Plan webhooks") has the spec, the docs that point at it, and this plan.

**The performance plan** ([docs/performance.md](../../performance.md), slice 2) also adds a retry schedule per kind, and wants it in before webhooks, along with lanes so a long import can't hold up quick jobs (the runner runs four jobs at once across every kind, so today a 100-link import can make deliveries wait). If that slice has landed when you start, skip Task 1 and use its schedule. If not, Task 1 is the smallest version of it, and the performance slice builds on it.

## Global Constraints

- Every rule in `AGENTS.md` applies: routes mirror the API (a folder per path part, `[param]`, a file per method, `index.ts` only registers); words people read go in `apps/web/src/locales/en.json`; the app's `Dialog` and `AlertDialog` already become drawers below 768px, so use them; logical CSS classes only; readable, expanded code; match the code around you.
- Event names, exactly: `recipe.created`, `recipe.updated`, `recipe.deleted`, `recipe.restored`, `webhook.test`. Envelope body: `{"type":…,"timestamp":<event createdAt, ISO>,"data":…}`, made by `JSON.stringify` once and signed as sent.
- Every `data` starts with `household: { id, name }`, `by: { id, name } | null`, `via: "app" | "api" | "mcp" | "merran"`, `key: { id, name } | null`. Recipes are `{ id, slug, title, url }`, with `title` from `Recipe.name` and `url` `${publicUrl}/recipes/${slug}`, or null without `MERRAN_PUBLIC_URL`.
- Headers: `webhook-id` (`msg_` + the event's UUID, the same on every try), `webhook-timestamp` (seconds, when sent), `webhook-signature` (`v1,` + base64 HMAC-SHA256 of `${id}.${timestamp}.${body}`, keyed with the base64-decoded part after `whsec_`; several space-separated during the 24 hours after a rotation), `content-type: application/json`. The fetcher's `user-agent` (`Merran/<version> (+https://merran.app)`) is left alone.
- Secret: `whsec_` + base64 of 32 random bytes. The address, secret, previous secret and extra headers are each a sealed `Secret` row (`deps.settings.seal` / `open`); only the host (`URL.host`) is kept in the clear. Deleting a webhook removes its `Secret` rows explicitly.
- Retry waits, in ms, after tries 1 to 7: `[5_000, 300_000, 1_800_000, 7_200_000, 18_000_000, 36_000_000, 36_000_000]`; `maxAttempts` 8. Timeout 10,000 ms. Any 2xx is delivered. `410` pauses at once. Redirects are failures. The first 1,024 characters of the answer are kept; the fetcher's `maxBytes` is 1,000,000.
- Limits: 10 webhooks a household; 5 extra headers, names `/^[A-Za-z0-9-]{1,64}$/`, values at most 1,000 characters, never `content-type`, `content-length`, `host`, `user-agent` or anything starting `webhook-` (case-insensitive); addresses `http:` or `https:`, no user name or password, at most 2,000 characters; names 1 to 80 characters. Events and deliveries are kept 30 days.
- Settings: `webhooks.enabled` (`MERRAN_WEBHOOKS`, switch, default `true`), `webhooks.homeNetwork` (`MERRAN_WEBHOOKS_HOME_NETWORK`, choice `off` | `all` | `chosen`, default `off`), `webhooks.homeNetworkHouseholds` (list of household ids, no env, default `[]`). All server-level.
- Error codes and messages (exact): `webhooks_off` "Webhooks are turned off on this server." (403); `webhook_not_found` "There's no such webhook." (404); `delivery_not_found` "There's no such delivery." (404); `too_many_webhooks` "A household can have up to 10 webhooks." (409); `webhook_address` "Use a full address, starting with http:// or https://." or "Put a user name or password in a header, not the address." (400, field `address`); `webhook_home_network` "This address is on your home network. The server admin can allow that in Settings → This server → Webhooks." (400, field `address`); `webhook_events` "Pick at least one event." (400, field `events`); `webhook_headers` "That header is one Merran sets itself." (400, field `headers`); `delivery_waiting` "That delivery is still being tried." (409); `webhook_paused` "Resume the webhook first." (409).
- Routes are session-only (`SESSION_SECURITY`, `asHouseholdAdmin`), never `openToKeys`, and refuse with `webhooks_off` while the module is off.
- Recipes brought in by `importRecipe` (other apps, Merran archives) and background runs (nutrition, AI photo runs, tidy runs) record nothing. Bulk tag changes, tag renames, stars and cooking notes record nothing.
- The household export is an explicit list of tables (`services/transfer/export.ts`), so webhooks stay out of it with no change there.
- After API changes: `pnpm --filter @merran/server openapi`, then the web and extension `api` scripts. These fail from Git Bash on this machine; run them in PowerShell: `$env:pnpm_config_cache_dir = "D:\Development\Mise\.local\pnpm-cache"; pnpm --filter @merran/web api; pnpm --filter @merran/extension api`. The two `schema.d.ts` files must match.
- Migrations: `pnpm --filter @merran/server db:test-postgres` (Docker), then `pnpm --filter @merran/server db:migration webhooks`. Read both files; the SQLite generator can drop enum checks. If Docker won't start, write the Postgres migration by hand from the SQLite one.
- Prettier only from the root (`pnpm format`) or on named folders, never on `docs/`.

## Review Focus

1. **A recipe title with accents and emoji** ("Crème brûlée 🍮"). The signature is over the UTF-8 bytes that were sent, so `standardwebhooks` verifies the raw received body. Owned by Task 7.
2. **A webhook deleted while its delivery waits for a retry.** The job finds no delivery and finishes quietly: no failed job, no error log. Owned by Task 7.
3. **The server admin stops allowing the home network after a household saved a LAN address.** The next try is refused as a private address and counts as a failure, then retries and pauses like any other. Owned by Task 7.
4. **A member, an API key, or another household's admin.** A member gets 403 `not_household_admin`, any API key 403 `api_key_not_allowed`, and another household's webhook id 404 `webhook_not_found`, on every route. Owned by Task 8.
5. **Saving a recipe without changing anything.** No `recipe.updated` is recorded. Owned by Task 9.

    em: EntityManager,
    householdId: string,
    event: {
      type: T
      data: EventData<T>
      actor?: Actor
      /** One webhook only, with no job: Send a test tries it straight away. */
